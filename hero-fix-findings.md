(`height:auto; aspect-ratio:16/9; object-fit:cover`) never applied; only
`img{max-width:100%}` applied and width/height attrs forced 800px-tall heroes.

- `img_tag()`: hero imgs (`kind=='hero'` only) now render
  `className="hero-img"` (className, not class — JSX).

  `minmax(0,1.15fr) minmax(0,.85fr)`; `.hero-img` gains `max-width:520px`
  (keeps `height:auto` — required so aspect-ratio is not defeated).
- Theme untouched (teal-navy gradient, white H1, rust button #9a3412).

Measured (hero-fix.json, all 46 routes, computed style):

  1,248–1,377px @390.

  @1440 (min 358 hubs, max 462 insurance page — text-col driven),
  405–792px @390. Computed: class `hero-img`, aspect-ratio `16 / 9`,
  object-fit `cover`, max-width `520px`, width `498.094px`.
  0 pages with img taller than 320px @1440 or 230px @390.
- Served variants: -800w @1440, -400w @390 (srcset, sizes 600px / 90vw).
  Note: `naturalWidth` in Chromium for srcset imgs reports the slot width
  (600 @1440 / 351 @390), NOT the file's intrinsic size — verified the files

## 7. Extra fix found + fixed in this round (pre-existing, not caused by heroes)

Home page had a same-page duplicate: `flooded-floor-7924140.webp` on BOTH the
appliance-leak service card and the Richardson area card. Cause: home renders
two card sections in separate `cards_html()` calls, each with its own `chosen`
set, so a swapped image could repeat across sections. Fix in `gen4.py`:
`cards_html(..., chosen=None)` shared set, home passes one `home_cards` set
to both calls. After rebuild: home 37 `<img>` tags, **0 files used more than
once**; Richardson card now shows `suburban-home-32711440.webp` (its own body
image). No content/link/word change.
